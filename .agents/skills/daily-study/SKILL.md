# 每日学习会话（daily-study）

仓库根 = 当前工作目录（含 `AGENTS.md` / `ROADMAP.md` / `STATE.md` / `ts/`）。
工作区在 `ts/`，所有命令都在 `ts/` 下执行。

> 逐条清单：`docs/guides/start-task.md`（起 task）、`docs/guides/commit-guide.md`（封版）。
> 本文件负责**路由与红线**，清单细节以 guides 为准。

## 何时用

- 用户新开会话说「今天做什么 / 今天要干嘛 / 开始刷题」→ 走 **开场**。
- 用户中途给反馈 / 卡住 / AC → 走 **中场**。
- 用户说今天做完了 / 让调整计划 → 走 **收尾**。

---

## 开场（新会话，用户问今天做什么）

**1. 先摸底**（还没读过就读）：`ROADMAP.md`、`STATE.md`、`AGENTS.md`；
最近 2–3 份 `ts/docs/daily/*.md`；`git log --oneline -20`（看最近进度、节奏、卡点）。
据此判断今天该「继续当前类型 / 回补 / 复习为主 / 进阶」。

**2. 先问，别直接写**：说明今天建议（类型 + 选题 + 题量），并**明确问用户**：

> 「要我现在起**今日任务文档**吗？默认 <N> 道（<题号 题名>）。也可以调整题量 / 换类型 / 先热身。」

**用户确认前，不要运行 `npm run day`，不要创建 / 修改任何文件。**

**3. 生成今日文档骨架**（同意后）：

```bash
cd ts
npm run day              # 默认 plan.dailyMin(2) 道新题 + 到期复习
npm run day -- --units 1 # 用户累，减量
npm run day -- --units 4 # 状态好，加量
npm run day -- --pattern linked-list   # 今天专攻某类型
```

会写 `ts/docs/daily/<今天>.md`，并打印：当前类型、新题、到期复习、未完成手写 drill。

**4. 补全文档里属于 AI 的部分**（用 edit 局部填，别重写整份）：

- **今日主题**：一句话——今天练什么、为什么是它。
- **今日学习内容（讲解）**：先 `npm run learn -- <pattern>` 看预习卡，再写 **5–10 分钟能读完** 的讲解：是什么 / 核心思想 / TS 模板骨架 / 易错边界。**只讲套路，不给完整题解**。
- 每道题的 **识别信号**：看到什么关键词想到这个套路。

**5. 用中文清单告诉用户**，必须含：**题号 + 中文名 + 英文名 + 难度 + 链接 + 建目录命令**；以及今日复习题、未完成的手写 drill。

**6. 提醒红线**：读完讲解立刻动代码；**超过 20 分钟没写代码就跳过**。

---

## 中场（用户给反馈 / 卡住 / AC）

- **卡住**：只回答「为什么 / 概念 / TS 语法」，**不给完整实现**。先把「卡在哪」写进今日文档的「练习过程 · 反馈与讨论」。
  先让用户自己想 25–30 分钟。
- **AC / 讲完思路**：把关键讨论、边界、更好写法补进今日文档（对应题的「结果」打勾 + 反馈区）。
- **不要硬补**：顺利、没有值得记的，就留空或只写一行结论。
- 同步更新每题 `ts/problems/<编号>-<slug>/notes.md` 的留白（思路 / 卡点 / AI 复盘 / 标准要点）。
- **节奏校准**：用户对某知识点明显吃力、或同一类型停留超预期时，**主动问**：
  > 「这个概念原计划用 N 次（天）过，现在比较吃力，要不要放慢加深——比如延长到 M 次、减少每日新题、加基础题和复习？」
  用户确认后记进今日文档并据此调整；**不要不声不响地硬推**。反之明显轻松也主动提议加量/进阶。
- 记录完成：`npm run solve -- <题号> [--first] --min <耗时>`（自动 commit，计入复习）。

---

## 收尾（今天做完）

1. 回填今日文档的「**复盘 & 对计划的调整**」。
2. 判断要不要调整计划（**说明原因**）：
   - 太轻松 → 提高 `dailyMin`（改 `ts/scripts/plan.mjs` 后 `npm run plan`），或让用户进阶下一个类型；
   - 太吃力 → **先问用户**是否放慢加深（例：原计划 3 次过 → 延长到 5 次、减少每日新题、加基础题和复习），再调整。
   改 `ROADMAP.md` 对应状态行 + `STATE.md`，并在日志记一行。
3. 更新 `STATE.md`：阶段 / 当前类型 / 累计 / 下一步。
4. 提交：按 `docs/guides/commit-guide.md`（**先问用户**，同意才提交）。
5. 复习提醒：今日文档「今日要复习的题」里 **闭卷重写**，再 `npm run solve`。

---

## 硬规则

- **不假设用户「Java 时期全会」**：底层结构（堆 / 排序 / 链表操作…）当新内容恢复。
- 每次提题目都要 **题号 + 中英文名**（用户会去网上搜）。
- **AI 不给完整题解**；只给为什么 / 概念 / TS 语法 / 边界提示。
- 讲解是薄的：读完就动手，超过 20 分钟没写代码就停。
- 顺利时不硬补文档，卡住时记清「卡在哪、怎么解决」。
- 所有计划调整都要写进文档，不要只改代码。
