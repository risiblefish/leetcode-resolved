# 会话 SOP（daily-study）

仓库根 = 当前工作目录（含 `AGENTS.md` / `ROADMAP.md` / `OVERVIEW.md` / `ts/`）。
工作区在 `ts/`，所有命令都在 `ts/` 下执行。

> **本文件只讲协议路由**。决策模型 / 水位 / 心流 / Pitfall 机制在 `AGENTS.md §1、§4`，当前位置和下一份建议在 `OVERVIEW.md`。
> 逐条清单：`docs/guides/start-task.md`、`docs/guides/commit-guide.md`。

## 何时用

- 新会话 / 用户问「今天做什么 / 下一份」→ 走 **开场**
- 中途反馈 / 卡住 / AC → 走 **中场**
- 本份做完 / 让调整计划 → 走 **收尾**

---

## 开场

1. **摸底（只读）**：读 `OVERVIEW.md` → 最近 2–3 份 `ts/docs/daily/*.md` → `git log --oneline -20`。

2. **讲选题依据 + 本份目标**（透明可反驳）：
   > 「当前水位 **X**（近期信号：...），本份建议 **Y 道**：#A（中英文名 + 难度）、#B。
   > 目标：AC 两道 + 带回 ≥1 条 Z（新套路 / 新 TS 维度）。
   > **开本份吗**？也可以调量 / 换类型 / 换题。」

3. **用户确认前，不动任何文件**。得到同意再 `npm run day`。

4. **补全文档的 AI 部分**（用 edit 局部填，别重写整份）：
   - **本份主题**：一句话——练什么 / 为什么是它
   - **讲解**：先 `npm run learn -- <pattern>` 看预习卡 → 写 **5–10 分钟能读完** 的讲解（是什么 / 核心思想 / TS 模板骨架 / 易错边界）。**只讲套路，不给完整题解**。
   - 每题 **识别信号**：看到什么关键词想到这个套路

5. **输出中文清单**：**题号 + 中文名 + 英文名 + 难度 + 链接 + 建目录命令**，含到期复习题。

6. **红线提醒**：读完讲解立刻动代码；**>20 分钟没动代码就跳过预习**。

---

## 中场

- **卡住**：只回答「为什么 / 概念 / TS 语法」，**绝不给完整实现**。先让用户硬扛 25–30 分钟，把「卡在哪」写进 daily 反馈区。
- **AC / 讲完思路**：读代码复盘（表达、边界、复杂度、更自然的写法），保持讨论语气——先肯定可行部分，再指出可改进项。
- **碰到反直觉 TS 问题**（「我以为 X，TS 说 Y」）：daily 反馈区记一句「疑问 + 我以为 + 实际 + TODO: PF」，**收尾时**统一落 pitfall 卡（AGENTS.md §4）。
- **不要硬补**：顺利没有值得记的就留空。
- 记录完成：`npm run solve -- <题号> [--first] --min <耗时>`（自动 commit，计入复习）。

---

## 收尾

1. **一字问**：本份感觉 **爽 / 一般 / 卡**？
2. **判断水位 / 心流信号**（AGENTS.md §1.2 规则表）：
   - 水位要调（升/降/维持）→ 必须说依据；用户可反驳
   - 继续当前节奏 / 换类型 / 加 TS 挑战 → 都要讲清楚为什么
3. **收尾时落 pitfall 卡**（如果有反直觉 TS 问题的 TODO）
4. **刷新 `OVERVIEW.md`**：
   - 当前类型水位 + 必做进度
   - 近期信号（最近 2-3 道的 AC / 代码质量 / 讨论质量）
   - 下一份建议 + 判断依据
   - TS 侧覆盖度（如果新增了 pitfall 卡）
5. **提交**（按 `docs/guides/commit-guide.md`）：先问用户同意，才 commit。
6. **复习提醒**：到期复习题闭卷重写后 `npm run solve`。

---

## 硬规则（和 AGENTS.md §3 对齐）

- **不假设用户「Java 时期全会」**：底层结构也当要恢复的内容
- 每次提题目都要 **题号 + 中英文名**
- **AI 不给完整题解**，只给为什么 / 概念 / TS 语法 / 边界提示
- 讲解是薄的：读完就动手，>20 分钟没写代码就停
- 顺利时不硬补文档，卡住时记清「卡在哪 / 怎么解决」
- 所有决策（选题 / 调水位 / 换类型）都要写清依据
