- **核心思想**：用 O(n) 的额外空间（Map/Set）把『查找/计数』从 O(n) 降到 O(1)。遍历时边读边把已经见过的信息存起来。

## 我的思路（先写再做，哪怕写错）

**钩子：多数派抵消不完，最后站着的就是它。**

假设所有数在打群架：同数抱团，不同数**一换一同归于尽**。多数元素出现次数 > n/2，其他所有数加起来 ≤ n/2 ——
即算其他数全部用来和多数元素对消，多数元素至少还剩 1 票。

实现：维护候选人 `candidate` 和它的**净剩票数** `cnt`：

- `cnt === 0` → 台子上没人，当前数上，`cnt = 1`
- 当前数 == candidate → 自己人，`cnt++`
- 当前数 != candidate → 来踢馆的，`cnt--`

## 卡点（卡在哪 / 看了什么提示）

**算法侧**：第一次 AC 用的是 Map 哈希计数（O(n) 空间），本份闭卷重写才换成 Boyer-Moore。

**TS 侧（真卡点）**：原本写 `let candidate;`（先声明后赋值）—— strict 下报 `TS18048 / TS2322: possibly 'undefined'`。
为了绕开报错，当时把循环条件溱成了 `for (let i = 0; i < candidate; i++)`，结果**逻辑错**：
`candidate` 是「内容」，`i` 是「进度」，两者不是一个量纲。

**根因**：Java 的 `int candidate;` 直觉在 TS 不成立 —— TS 没有「先声明后赋值」的免费午餐。
**已落卡**：[PF-0003](../../docs/pitfalls/PF-0003-no-late-assignment-in-strict-ts.md)

**反例（BM 照妖镜，已写进测试）**：`[1,2,2,2,2]`（错版→1）、`[9,1,9,1,9,1,9]`（错版→undefined）、`[1,9,9,9,9]`（错版→1）。
注意：官方示例 `[3,2,3]`、`[2,2,1,1,2,2,1]` **恰好都能骗过错版** —— 这就是为什么必须自己造反例。

## 可改进点 / 标准要点

1. **钩子**：多数派抵消不完，最后站着的就是它
2. **`cnt` 的语义**：是「净剩票数」，**不是** `candidate` 的真实计数 —— 两者不一样，别混
3. **识别信号**：「出现次数严格 > n/2」「要求 O(1) 额外空间（排序/哈希都做不到）」→ BM
4. **前提**：题目**保证**多数元素存在才能一遍过；不保证时要跑第二遍数一下真实次数
5. **变体**：求「出现 > n/3」→ BM 扩展版（维护**两个**候选人）；这是检验「钩子是否真属于你」的迁移题
6. **TS 坑**：`let candidate;` / `let candidate = undefined;` 在 strict 下都会变成 `number | undefined`，必须给初值或显式声明 + `!`（PF-0003）

**复习时要达到**：闭卷从空白写出 BM，并**主动说出** `[1,2,2,2,2]` 这类反例（能说出来 = 真懂了循环边界为什么不能跟 `candidate` 有关）。
