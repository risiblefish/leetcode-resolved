## 我的思路（先写再做，哪怕写错）

**钩子：按左端点排队，看能不能接上；接上就延长右端（取 max），接不上就另起一段。**

1. 按左端点升序排序 → 能合并的区间一定相邻，只需比较「当前区间左端」与「上一段右端」
2. `pre` = 答案里最后那一段；`cur[0] <= pre[1]` → 重叠 → 合并（`pop` 旧的、`push` 新的）
3. 合并时右端必须 `Math.max(cur[1], pre[1])`
4. `cur[0] > pre[1]` → 接不上 → `cur` 自己变成新的一段

## 卡点（卡在哪 / 看了什么提示）

**第一版 WA，两个**互相独立**的根因**（都记下来，这是本题最有价值的部分）：

1. **判重叠用了严格不等号**：`intervals[i][0] > pre[0] && intervals[i][0] < pre[1]`
   → 漏掉「端点相接」：`[[1,4],[4,5]]` 判成不重叠，输出 `[[1,4],[4,5]]`（应 `[[1,5]]`）
   → 同时 `> pre[0]` 把「左端点相同」的情况（`[[1,3],[1,5]]`）也排除了
2. **合并时右端直接取新区间的右端**：`[pre[0], intervals[i][1]]`
   → 小区间被大区间**包住**时，会把大区间**缩回去**：`[[1,10],[2,3]]` 输出 `[1,3]`（应 `[1,10]`）

修法：`cur[0] <= pre[1]`（可接） + `Math.max(cur[1], pre[1])`（右端不缩）。**两个 bug 都要各配一个反例**，否则改一个漏一个（见测试里的 3 条反例）。

**TS 侧**：没卡。

## AI 复盘（AC 之后也值得看）

**好的**：

- 「先排序再扫描」的大方向对，且排序动的是副本（`[...intervals]`），**没把入参排序坏**
- 修 bug 时**两个根因都改到了**（判重条件放宽 + 右端取 max）—— 很多人只改一个，然后被另一组用例打回来
- 把「上一段」`pre` 单独存变量，扫描主线清楚

**可改进**：

- `pop + push` 是「修改答案最后一个区间」的**绕路写法**。直接改更顺：
  ```ts
  const last = ans[ans.length - 1];
  if (cur[0] <= last[1]) last[1] = Math.max(last[1], cur[1]);
  else ans.push([...cur]);
  ```
  或者干脆不存数组、只存 `let [s, e]` 扫描，最后统一 push —— 更省心（不用管别名）
- 场上是把输入区间的**引用** push 进答案（`ans.push(intervals[i])`）；一旦调用方改了输出，输入也会变。agent 已规范化为 push 副本（透明披露）
- 排序比较函数 `(a, b) => a[0] - b[0]` 正确（用减法而不是 `a[0] > b[0]` 返回 boolean，避免「返回 true 被当 1」的经典坑）

**没应改**：

- 先扫一遍就 push 第一个区间的写法好；`pre` 命名直白

## 可改进点 / 标准要点

1. **钩子**：按左端点排队，看能不能接上
2. **核心不变式**：扫描中 `pre` 维护的是「当前合并段的 `[起点, 目前已达最大右端]`」—— 因为排过序，起点永远是最小左端，右端取 max
3. **两个致命细节**（本题的两个坑）：
   - **端点相接算重叠**（`cur[0] === pre[1]` 要合并）→ 用 `<=`
   - **右端取 max**（被包住的小区间不能把大区间缩回去）→ `Math.max`
4. **复杂度**：O(n log n) / O(n)；已排序输入可省排序但那不是本体（进阶追问「是否有序」「是否原地」）
5. **边界**：只有一个区间；完全分离；乱序输入（先排序）；`[[1,1],[2,2]]`（值相同但不相接）
6. **反例清单**：`[[1,4],[4,5]]`→`[[1,5]]`；`[[1,4],[4,4]]`→`[[1,4]]`；`[[1,3],[1,5]]`→`[[1,5]]`；`[[1,10],[2,3]]`→`[[1,10]]`
7. **顺手的好习惯**：排序/翻转都动副本，不改入参；输出里放副本，避免和输入别名
8. **复习时要达到**：闭卷写出扫描版，并**主动说出两个反例**（端点相接 / 被包住），证明不变式真懂了
