## 我的思路（先写再做，哪怕写错）

**钩子：先存尾巴，再从后往前倒着搬，最后回填 ——「倒着搬，不踩自己」。**

1. `k %= nums.length`（k 可以大于 n）
2. 先把「会绕到前面去」的尾部 k 个暂存起来（`slice`）
3. 剩下的部分整体后移 k 位：**必须从后往前** `nums[i + k] = nums[i]`，否则前面刚写的值会把后面还没搬的覆盖掉
4. 把暂存的 k 个写回 `[0, k)`

## 卡点（卡在哪 / 看了什么提示）

**算法侧**：没卡。闭卷一次写出，`k % n` 和「从后往前搬」两步都是当场想清楚的。

**TS 侧（自己检查时补的）**：

- `slice(-k)` 在 **k === 0 时返回整个数组**（`slice(-0)` 等价 `slice(0)`）—— 本题因为 k=0 时后面两个循环都不干活，**歪打正着没出错**，但这是颗雷（已改成 `slice(n - k)`）
- 空数组时 `k % 0` 是 `NaN`，循环条件 `i >= 0` / `i < NaN` 都不成立，**同样歪打正着** —— 但依赖 NaN 比较来「碰巧正确」不是好习惯（已加 `if (n === 0) return`）

## AI 复盘（AC 之后也值得看）

**好的**：

- 「从后往前搬」抓住了本质：**搬移方向必须与目标位移方向相反**，才不会自己踩自己
- `k %= n` 处理了 k > n；`void` 签名 + 原地修改，语义对
- 暂存 k 个而不是 n 个：比整个复制省空间（O(k) 而不是 O(n)）

**可改进**：

- **最优解是 O(1) 空间的「三次翻转」**（题目进阶追问就想要这个）：
  1. 整个数组翻转 → 2. 翻转 `[0, k)` → 3. 翻转 `[k, n)` → 得到右移 k 位
  （「翻转」= 双指针交换，原地、O(1)）
- 写法上 agent 做了两处规范化（透明披露）：`slice(-k)` → `slice(n - k)`；补 `n === 0` 早退 —— 都是把「碰巧对」变成「显然对」
- 用 `pop/push` 的一行式也可以（`nums.unshift(...nums.splice(-k))`），但那是 O(k) 额外 + 频繁移动，不如翻转

**没应改**：

- 命名 `tail` / `pre` 这类直白名字比 `arr2` 好，保留

## 可改进点 / 标准要点

1. **钩子**：先存尾巴，再从后往前倒着搬，最后回填
2. **三次翻转（必练，O(1) 空间）**：全翻 → 翻前 k → 翻后 n-k；口诀「**整体翻，前后各翻**」
3. **核心不变式**：搬移方向与目标位移方向**相反**（左移从前往后搬、右移从后往前搬），否则覆盖未处理数据
4. **边界**：`k %= n` 必须先做；`k === 0` 与 `k === n` 结果都等于原数组；空数组；单元素
5. **两条路的取舍**：暂存法 O(n)/O(k) 好写；三次翻转 O(n)/O(1) 才是「原地」的标准答案
6. **TS 关联**：`slice(-0)` 返回整个数组（不是空）；负下标/越界在 JS 里是**静默**的，见预习卡番外 C
7. **复习时要达到**：**闭卷写出三次翻转版**并说清「为什么翻转三次就等于右移 k」
