## 这份要学 / 复习什么（薄预习）

> 来自预习卡：`npm run learn -- array-hash`

- **核心思想**：用 O(n) 的额外空间（Map/Set）把『查找/计数』从 O(n) 降到 O(1)。遍历时边读边把已经见过的信息存起来。
- **本题专属（这题不是哈希，是前后缀乘积）**：每个位置的答案 = **左边所有数的积 × 右边所有数的积**。
  禁用除法 + 要求 O(1) 额外空间 → 两次扫 + 滚动变量。
  和 #121 同族：都是「扫一遍 + 一个滚动变量累积信息」模板。
- **识别信号**：
  - 「每个位置都要依赖其他位置的汇总」+ 不许用某种运算（除法 / 累加）
  - 要求 O(1) 额外空间 + 一次扫做不完 → 两次扫 + 滚动变量
- **易错 / 边界**：
  - 空积 = 1（**不是 0**）：`ans[0] = 1`、`rPre = 1`
  - 右扫顺序：**先用后更新**（反了错一位）
  - 右扫下界：`i >= 0`（不是 `i > 0`，否则 ans[0] 漏算）
  - 含 0 天然处理，不用特判

## 我的思路（先写再做，哪怕写错）

**钩子：每个位置的答案 = 左积 × 右积，空积 = 1。** 禁用除法 → 分段扫；要求 O(1) 空间 → 答案数组兼 L[]，右积用滚动变量。

**三阶段推导**（从朴素到最优）：
1. **朴素**：开 `L[]` `R[]` 两个辅助数组，`L[i] = ∏ nums[0..i-1]`、`R[i] = ∏ nums[i+1..n-1]`，`ans[i] = L[i] * R[i]`。O(n) 时间，**O(n) 空间**。
2. **省 L[]**：让答案数组直接承担左积的角色（第一遍扫完 `ans[i] == L[i]`）。
3. **省 R[]**：从右往左扫时用滚动变量 `rPre` 代替，初始 1；**先用**（`ans[i] *= rPre`）**后更新**（`rPre *= nums[i]`）。最终 **O(1) 空间**。

## 卡点（卡在哪 / 看了什么提示）

**算法侧**：心法秒抓到（左积 × 右积），但第一版实现**没想到空间优化**，直接写了朴素 O(n) 空间版（两个辅助数组）。AI 提示才意识到可以压 O(1) —— 本份目标就是 O(1) 版。

**本次踩坑（两处，都是本来能避免的）**：

1. **右扫循环下界写成 `i > 0`**（朴素版）→ `right[0]` 从未赋值 → `ans[0] = 1 * undefined = NaN` → LeetCode 的 `JSON.stringify(NaN) === "null"` → 报错 `[null, 12, 8, 6] is not valid value for the expected return type integer[]`
   - **根因**：心理模型把"初始化已覆盖 n-1"误以为"只要再处理中间"，忘了循环要覆盖 `0..n-2` 整段
   - **抓它的测试**：造一个 n=4 的用例看 `ans[0]`（已加进 solution.test.ts「右扫边界反例」）
   - 不立 PF 卡（纯通用循环边界细节，非 TS 反直觉）
2. **PF-0005 复发**：当天早上刚立卡 PF-0005（`new Array(n)` 是 `any[]`），本题三处 `new Array(nums.length)` 全没加泛型 → TS 本可以在 `right[0] = undefined` 时帮忙（配合 `noUncheckedIndexedAccess`），但 `any[]` 下保护全失效 → 坑没拦住
   - **教训**：**立卡当天就能复发**，说明"写习惯"没覆盖；下次 `new Array(` 要形成肌肉记忆的"必带泛型"反射
   - 已改成 `new Array<number>(nums.length)`

## AI 复盘（AC 之后也值得看）

**好的**：
- **心法秒抓**：禁用除法 → 分段扫（左积 × 右积），这一步没卡
- **O(1) 版的"先用后更新"顺序一次写对**：`ans[i] *= rPre; rPre *= nums[i]` ——这是本题唯一容易写错的地方，没踩
- **注释内置文档**：`//此时 ans[i] = left[i]` / `//rPre = r[i+1]` 把隐含状态写明，复习时自己回来看就能接得上
- **变量命名**：`rPre` 虽然潦草，但注释里标了含义，可读
- **听进去了 PF-0005**：第二版主动把 `new Array` 改成了 `new Array<number>`（没完全改干净 —— `const ans: number[] =` 这个冗余标注还在，但不影响正确性，不强改）

**可改进（不改也行）**：
- `rPre` → `rightProd` / `right` 更惯用；`rPre` 的 Pre 容易被误读为 prefix（这题 prefix 是左积）
- 第一版的朴素实现**没本地跑 npm test**，直接提交 LeetCode 导致踩了 null 坑 —— 下次改完**先跑本地测试**（现在的 solution.test.ts 新增的「右扫边界反例」用例会抓住这类 bug）

**没应改**：
- 两次扫 + 滚动变量就是本题标准解，不用再秀分治 / 其他
- 不特判 0 是对的，让算法自然处理最干净

## 可改进点 / 标准要点

1. **钩子**：每个位置答案 = 左积 × 右积；空积 = 1
2. **三阶段心法**：朴素 O(n) 空间 → 省 L[] → 省 R[]（滚动变量）→ O(1)
3. **顺序铁律（最易错）**：右扫时**先用 rPre 乘到 ans[i]，再用 nums[i] 更新 rPre**。反了错一位。
4. **循环下界**：右扫是 `for (i = n-1; i >= 0; i--)`，**要包含 0**。本次踩的坑。
5. **空积初始化**：`ans[0] = 1` 和 `rPre = 1` —— 空积是 **1 不是 0**（0 会让答案全是 0）
6. **含 0 天然处理**：1 个 0 / ≥2 个 0 都不用特判，两次扫描法自洽
7. **复杂度**：时间 O(n)，空间 O(1) 额外（题目保证输出不计）
8. **TS 关联**：
   - **[PF-0005](../../docs/knowledge/language/PF-0005-new-array-is-any.md) 复发**——`new Array(n)` 必须跟 `<T>`，否则 any[] 让 TS 失去 undefined 保护
   - **[PF-0008](../../docs/knowledge/language/PF-0008-negative-zero.md) 新立**——负数×0 产生 `-0`，vitest.toEqual 区分 `-0` 和 `+0`，但 LeetCode 序列化成 `0`（所以线上 AC 本地炸）
9. **同族题**：#121 买卖股票（滚动变量维护"目前最小"）、#53 Kadane（滚动变量维护"以 i 结尾的最大和"）—— 都是"扫一遍 + 一个变量累积信息"模板
10. **复习时要达到**：闭卷写出 O(1) 版 + 口头说清「为什么空积 = 1」「为什么要先用后更新」

**踩坑**：PF-0005（复发）· PF-0008（新立：负数×0 产生 `-0`，本地测试炸、线上 AC）
