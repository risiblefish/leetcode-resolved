## 这份要学 / 复习什么（薄预习）

> 来自预习卡：`npm run learn -- array-hash`

- **核心思想**：用 O(n) 的额外空间（Map/Set）把『查找/计数』从 O(n) 降到 O(1)。遍历时边读边把已经见过的信息存起来。
- **识别信号**（看到这些条件就该想到该套路）：
  - 题目要你判断『是否出现过』『两数之和』『分组』→ 哈希
  - 要求 O(n) 但暴力是 O(n²) → 用哈希/前缀和降复杂度
  - 需要统计次数/去重/求交集 → Map / Set
- **易错 / 边界**：
  - 空数组 / 单元素
  - 有重复元素时返回下标还是值
  - TS 里字符串不可变，改字符要先拆成数组
  - Map 的键是值语义（对象当键要注意引用）
- **本题专属**：**「查在不在」用 Set + 「每个元素只数一次」** —— 本题要求 O(n)，所以不能排序（排序是 O(n log n)），也不能对每个数都往两边扫（那是 O(n²)）。

## 我的思路（先写再做，哪怕写错）

**钩子：相邻的数用 Set 找；数过的链当场删掉 ——「数一条，删一条，绝不重数」。**

1. 所有值塞进 `Set`（自带去重）
2. 任取表里一个还在的 `val`：`left = val - 1` 往左伸、`right = val + 1` 往右伸，**伸到谁就把谁 `delete`**
3. 整条链数完后它就从表里消失了 → 后面的循环不会再数同一条链 → **每个元素最多被删一次**，总工作量 O(n)
4. 答案取所有链长的最大值

## 卡点（卡在哪 / 看了什么提示）

**算法侧**：没卡。但这里有一个**容易心虚的点**，值得写清楚：

> 「**一边 `for...of` 遍历 Set，一边 `delete` 里面的元素**，安全吗？」

- 安全。Set 的迭代器在删除「**还没访问到**」的元素时，那些元素会被跳过；删除「**已经访问过**」（包括当前这个）的元素没有任何影响
- 本题里 `delete` 掉的都是「已经在本次计数里被算进去」的数 → **跳过 = 不重复数**，正是想要的效果
- 剩下的 `val` 自己留在表里没关系：它要么是链的起点，要么这条链已经被 delete 光了

**TS 侧**：没卡。顺手写对了两处：`Set<number>` 带泛型、`seen.delete(left--)` 的「先取值再自减」。

## AI 复盘（AC 之后也值得看）

**好的**：

- 「数过的链当场删」是**真正把复杂度降下来**的那一步 —— 不是「每个数都往两边扫一遍」的伪 O(n)
- 双向伸展（同时找左找右）比「只从链头起跳」少一次 `has` 判断，且在删除策略下更自然
- `while (seen.has(left))` 用 Set 做 O(1) 存在性判断，正是本类型的核心心法
- 边界天然正确：空数组 → `curMax` 保持 0；单元素 → 1

**可改进**：

- 另一种等价写法是「**只从链头起跳**」：
  ```ts
  for (const val of seen) {
    if (seen.has(val - 1)) continue;   // 不是链头，跳过
    let len = 1;
    while (seen.has(val + len)) len++;
    best = Math.max(best, len);
  }
  ```
  **不删表**、不边遍历边改，更好讲；复杂度同为 O(n)（因为只有链头会展开）。缺点：每个数多一次 `has` 询问
- 若想彻底避免「边遍历边改」的心智负担，可以先 `for (const val of [...seen])` 拍快照（本解法会多 O(n) 空间，不推荐，知道即可）
- 写法上 agent 做了一处规范化（透明披露）：`if (!seen.has(val)) seen.add(val)` → `seen.add(val)`（`Set.add` 本来就幂等去重）
- 命名 `left` / `right` 清楚；`curMax` 可叫 `bestLen` 更贴语义

**没应改**：

- 用 `delete` 减工作量这个巧劲保留 —— 这是本题的亮点，比「不删表的链头版」更能体现实质上的「每个元素只数一次」

## 可改进点 / 标准要点

1. **钩子**：相邻的数用 Set 找；数过的链当场删 ——「数一条，删一条，绝不重数」
2. **核心不变式**：`seen` 里剩下的都是**还没有被任何链数过**的数
3. **为什么是 O(n)**：每个元素最多被 `delete` 一次 → 内层 `while` 的总步数是 O(n)，不是「每个数都 O(n)」
4. **两条等价路线**：①删表式双向伸展（本解）②只从链头起跳（`!seen.has(val - 1)`）
5. **识别信号**：无序数组 + 「最长连续长度」+ **要求 O(n)** → 必然要用 Set（排序 O(n log n) 会被卡）
6. **连续性指数值连续**，不是下标连续；重复值要先去重（Set 天然去重）
7. **边界**：空数组 → 0；单元素 → 1；重复值不重复计数；**负数也连续**（`[-1,0,1]` → 3）；不连续的值（`[5,7,9]` → 1）
8. **TS 关联**：`for...of` 遍历中删除未访问元素是安全的（删除被跳过）；`seen.delete(left--)` = 先删再减 1
9. **复习时要达到**：闭卷写出**链头起跳版**（更直白的那条路），并能说清「本解的删表版为什么同样是 O(n)」
