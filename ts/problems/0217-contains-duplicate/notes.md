## 这份要学 / 复习什么（薄预习）

> 来自预习卡：`npm run learn -- array-hash`

- **核心思想**：用 O(n) 的额外空间（Map/Set）把『查找/计数』从 O(n) 降到 O(1)。遍历时边读边把已经见过的信息存起来。
- **识别信号**（看到这些条件就该想到该套路）：
  - 题目要你判断『是否出现过』『两数之和』『分组』→ 哈希
  - 要求 O(n) 但暴力是 O(n²) → 用哈希/前缀和降复杂度
  - 需要统计次数/去重/求交集 → Map / Set
- **易错 / 边界**：
  - 空数组 / 单元素
  - 有重复元素时返回下标还是值
  - TS 里字符串不可变，改字符要先拆成数组
  - Map 的键是值语义（对象当键要注意引用）
- **本题专属**：**「判重」的最优解是 `Set`，不是排序** —— 见下「可改进点」

## 我的思路（先写再做，哪怕写错）

**钩子：排序后，重复的必然相邻。**

先把数组复制一份并排序；相等元素排序后一定挨在一起，所以扫一遍相邻对
（`sorted[i]` vs `sorted[i+1]`）就能判定是否存在重复。

## 卡点（卡在哪 / 看了什么提示）

**算法侧**：没卡，但走了**次优路**：排序 O(n log n)。

**TS 侧**：两个小观察
- `[...nums]` 先复制再 `sort` —— 好习惯：`sort` 是原地排序，直接 `nums.sort()` 会改掉入参
- `sorted[i] == sorted[i + 1]` 用了 `==`（Java 习惯），TS 里数值比较用 `===` 更稳

## AI 复盘（AC 之后也值得看）

**好的**：
- 复制数组不改入参（`[...nums]`）—— 面试里被追问「能不能原地改」时有底气
- 循环上界 `sorted.length - 1` 卡得准，不会越界
- 边界选得全：空数组、单元素、`0` 是合法值、负数、重复出现在两端

**可改进（重要）**：
- **换 `Set` 版** ✅ **r1 已做到**（2026-10-10，38 秒，闭卷一次写对）：本题只问「有没有重复」，用 `Set` 边扫边查就是 O(n)：

  ```ts
  const seen = new Set<number>();
  for (const x of nums) {
    if (seen.has(x)) return true;
    seen.add(x);
  }
  return false;
  ```

  排序法是 O(n log n)。**除非题目额外要求「找出重复的那个元素」或「不许用额外空间」，否则 `Set` 才是标准答案**
- `==` → `===`
- `let ans`/索引写法都可以更 TS 一点（`for...of` + `seen`），但这不是重点
- 依赖「排序后相邻」时，`sorted[i+1]` 的类型安全**靠 `i < len - 1` 的边界**保证；本项目未开 `noUncheckedIndexedAccess`，所以 TS 不会帮你拦越界 —— 边界条件必须自己想清楚

**没应改**：
- 排序法的正确性没问题，只是复杂度不是最优

## 可改进点 / 标准要点

1. **钩子（Set 版）**：见过就 `has`，没见过就 `add`；命中即重复
2. **识别信号**：只问「有没有重复 / 是否出现过」+ 不要求返回下标或次数 → `Set`，O(n)
3. **为什么排序不是最优**：O(n log n) vs O(n)；排序法的价值在于「同时要输出重复元素本身」或「不许用额外空间」
4. **必写的边界**：`[]` → false；`[7]` → false；**`[0, 0]` → true（别拿 0 当哨兵）**
5. **反例对照**：`[5,1,2,3,4,5]`（重复值在排序后的两端）；`[-3,-1,-3,2]`（负数）
6. **TS 关联**：`Set` 是值语义、`has` 命中后无需再取值（所以没有 PF-0001 那个 `undefined` 问题）

**复习时要达到**：闭卷直接写 `Set` 版（O(n)），并能说清「排序法为什么不算达标」；再顺口说出「什么时候反而该用排序」。
→ ✅ **r1 已达标**（38 秒，`has` / `add` 顺序正确，`[0,0]` 这种 0 值边界也没被哨兵写法定偏）
