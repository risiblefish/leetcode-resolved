### 一、哈希一遍过（给 #1 用）

**是什么**：遍历数组时，一边把「见过的东西」存进 `Map` 里，一边在 Map 里查「我现在要的东西有没有已经见过」。暴力是双层循环 O(n²)；用哈希把「查找」从 O(n) 变 O(1)，整体降到 O(n)。

**核心思想**：把「还得找 X」转成「X 存在吗」。遍历第 `i` 位时问：**我需要的那个搭档，之前出现过吗？** 出现过就配对成功，没出现就把当前这个存进去等别人来配。

**TS 模板骨架**（半成品，别照抄；凭记忆默写一遍）
```ts
const seen = new Map<number, number>();  // 值 -> 下标
for (let i = 0; i < nums.length; i++) {
  const need = /* 你要找的搭档 */;
  if (seen.has(need)) return [seen.get(need)!, i];
  seen.set(nums[i], i);
}
```

**TS 新手易踩**
- `Map.get()` 返回 `V | undefined`，要么 `!` 要么先 `has` 判一下；strict 下不处理会红。
- 用 `new Map<number, number>()` 显式带泛型，别写 `{}` 当字典——TS 里对象字面量键是 string，和 number key 会打架。
- 「先存还是先查」顺序很关键：**先查再存**，否则 `[3,3] target=6` 这种会把自己当搭档。

### 二、一次扫描 + 维护最小值 / 最大差（给 #121 用）

**注意**：#121 虽然挂在「数组与哈希」类下，但它**不用哈希**。它是**线性扫描 + 单变量状态**的套路——这个套路后面 DP / 贪心 / 滑窗都会反复出现，先在最简单的壳子里把它练熟。

**是什么**：从左到右扫一遍数组，用一个（或几个）变量记录「到目前为止的某种最优值」，边扫边更新答案。空间 O(1)，时间 O(n)。

**核心思想**：想象你**只能从左往右看一次**（像看股价直播，不能回头）。对每个位置 `i`，问自己两个问题：
1. **如果我今天卖，最好的买入点是什么？**（答案就是「我见过的最小值」）
2. **用今天这个价卖，能赚多少？**（当前值 - 到目前为止的最小值）

每一步都更新「历史最小」和「历史最大收益」。

**TS 模板骨架**
```ts
let best = 0;              // 到目前为止的最大收益
let minSoFar = Infinity;   // 到目前为止的最小值
for (const x of nums) {
  minSoFar = Math.min(minSoFar, x);
  best = Math.max(best, /* 今天卖的收益 */);
}
return best;
```

**易错**
- `best` 初始化成 `0` 不是 `-Infinity`——题目规定不能亏本交易。
- `minSoFar` 必须**先更新再算收益**，否则会用「还没见过的最小值」去算，等于偷看未来。
- 数组为空 / 单元素时直接返回 0。

## 反馈与讨论

### 讨论 1 · TS 类型收窄不跨方法调用

**我以为**：`seen.has(k)` 判过了，`seen.get(k)` 的类型就不该是 `undefined` 了。
**实际**：TS strict 下仍然报 `Type 'number | undefined' is not assignable to type 'number'`。
**根因**：TS 的类型收窄只认「对**变量本身**的判断」，不认「对**同一对象的另一个方法调用**」。`has` 返回新的 boolean，无法改变后一句 `get` 的返回类型。
**修法**：A. `seen.get(k)!` 非空断言 / B. 先取出来 `const j = seen.get(k); if (j !== undefined) ...`。
→ 已落卡：**[PF-0001](../knowledge/language/PF-0001-map-has-get-narrowing.md)**（Map.has 判空无法让 .get() 的 undefined 消失）

### 讨论 2 · 要不要追求最优解？

**决策**：**现阶段不追绝对最优**。信心高。
**协议**：
1. 第一遍自己写到 AC，哪怕 O(n²) 暴力
2. AC 后看高赞题解，只问两件事：**复杂度低一个数量级吗 / 用了本质不同的套路吗**
3. 满足其一才回头闭卷重写；否则留一行 note 过
4. 复习（r1/r2/r3）闭卷重写时，才用「现在认为最合适」的解法
**不卷**：常数优化、执行时间排名、一行流炫技。
**例外**：题目硬性约束（如 O(n) required / O(1) extra space）必须按约束解。

### 讨论 3 · TS 的 const/let 和 Java 的 final 对应关系

**我以为**：想标"不变"是不是用 `final`？
**实际**：TS 没有 `final` 关键字。局部变量用 `const`（≈ Java `final 变量`），类字段用 `readonly`（≈ Java `final 字段`），`final class / method` TS 没有对应。
**关键坑**：`const arr = []; arr.push(1)` **合法**——`const` 保护"绑定"不保护"值内部"。Java `final` 也一样。想让值也不可变用 `readonly T[]` 或 `as const`。
→ 已落卡：**[PF-0002](../knowledge/language/PF-0002-const-let-vs-java-final.md)**（const/let vs Java final）
