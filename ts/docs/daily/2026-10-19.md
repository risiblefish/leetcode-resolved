#### 前后缀乘积（prefix-suffix accumulation）

**心法一句话**：每个位置的答案 = **左边贡献 × 右边贡献**。两次扫描把问题拆成两条独立的累积。

**为什么要有这个套路**：
- 本题禁用除法 → 不能 `total / nums[i]`
- 要求 O(1) 额外空间（输出数组不计）→ 不能开 `left[]` + `right[]` 两个数组
- 一次扫做不完 → 分段扫（左扫 + 右扫）

**三阶段推演**：

1. **最朴素**：开两个数组 `left[i] = ∏ nums[0..i-1]`，`right[i] = ∏ nums[i+1..n-1]`，答案 `ans[i] = left[i] * right[i]`。O(n) 空间。
2. **省一个数组**：把 `ans` 直接当 `left` 用（第一遍扫完 `ans[i] = left[i]`）。
3. **省另一个数组**：从右往左扫时，用一个**滚动变量** `right` 累积右边的积，边扫边乘到 `ans[i]` 上。**O(1) 额外空间**（输出不计）。

**TS 模板骨架**：

```ts
function productExceptSelf(nums: number[]): number[] {
  const n = nums.length;
  const ans = new Array<number>(n);          // ⚠️ 必须写 <number>，否则 any[]（PF-0005）

  // 第一遍：ans[i] = 左边所有数的积
  ans[0] = 1;
  for (let i = 1; i < n; i++) {
    ans[i] = ans[i - 1] * nums[i - 1];
  }

  // 第二遍：从右往左乘上右边的积
  let right = 1;
  for (let i = n - 1; i >= 0; i--) {
    ans[i] *= right;
    right *= nums[i];
  }

  return ans;
}
```

**易错 / 边界**：
- **数组含 0** 的三种情况（两次扫描法自动处理，不用特判）：
  - 0 个 0 → 正常
  - 1 个 0 → 只有那个位置是左右积，其他全是 0
  - ≥2 个 0 → 全是 0
- 单元素 / 空数组：题目保证 n ≥ 2，但健壮代码可以提前返回
- 第一遍 `ans[0] = 1`（左边没有数，空积 = 1，别写 0）
- 第二遍初始 `right = 1`（右边空积 = 1，同理）

**识别信号**：
- 「每个位置都要依赖其他位置的汇总」+ 不许用某种运算（除法 / 累加）
- 要求 O(1) 额外空间 + 一次扫做不完 → **两次扫 + 滚动变量**
- 和 #121（买卖股票）同族：那题是"维护目前为止的最小值"，本质也是前缀累积

### 反馈与讨论

**#238 两处踩坑**（详见 PF-0005 复发 + PF-0008 新立）：

1. **朴素版右扫循环边界 `i > 0`** → `right[0]` 没赋值 → `ans[0] = 1 * undefined = NaN` → LeetCode 序列化成 `null` 报错
   - 我以为：「初始化涵盖了 n-1，循环处理中间」
   - 实际：循环要覆盖 `0..n-2` 整段，应写 `i >= 0`
   - 解决：一个字符改 `>` → `>=`
   - 不立 PF（通用循环边界细节，非 TS 反直觉问题）

2. **PF-0005 当天立卡当天复发**：本题三处 `new Array(nums.length)` 全没带泛型
   - 教训：「写习惯」没覆盖；下次写 `new Array(` 要有「必带泛型」的肌肉反射
   - 已改成 `new Array<number>(nums.length)`

3. **新立 PF-0008**：**负数×零 = `-0`（IEEE 754）**
   - 我以为：`-0 === 0` 所以没关系
   - 实际：`vitest.toEqual` 内部用 `Object.is`——区分 `-0` 和 `+0`！本地测试炸，但 LeetCode `JSON.stringify(-0) === "0"` → 线上 AC
   - 解决：测试里加 `normalize = (arr) => arr.map(x => x + 0)` helper。不污染 solution。

**#1 / #121**：没踩坑。滚动变量模式 + 哈希一遍过都是最佳解。

**横向收获**：#238 O(1) 版的 `rPre` 滚动变量 ≡ #121 的 `lowest` ≡ #53 Kadane 的 `cur` —— **滚动变量模式**是 array-hash 类型里最核心的半个模板。今天连贯感很强。
