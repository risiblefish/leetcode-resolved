# 预习卡 · 数组与哈希

> 类型：`array-hash`  ·  随时回看：`npm run learn -- array-hash`

## 它是什么

数组是连续内存、支持 O(1) 随机访问；哈希表用『键』直接定位，平均 O(1) 查找/插入。两者都是最基础的容器，几乎所有题的输入载体。

## 核心思想

用 O(n) 的额外空间（Map/Set）把『查找/计数』从 O(n) 降到 O(1)。遍历时边读边把已经见过的信息存起来。

## 考什么 / 学什么

考你能不能想到『空间换时间』，以及把问题建模成键值对/频次表（分组、去重、找配对）。

## TS 模板骨架（半成品）

```ts
const seen = new Map<number, number>();
for (let i = 0; i < nums.length; i++) {
  const need = target - nums[i];
  if (seen.has(need)) return [seen.get(need)!, i];
  seen.set(nums[i], i);
}
```

## 常见变体

- 配对（两数之和）
- 分组（键 = 某种特征，如排序后的字符串）
- 去重 / 求交并集（Set）
- 频次 Top K（Map 计数 + 排序/堆）
- 前缀和 + 哈希（和为 K 的子数组）

## 易错 / 边界

- 空数组 / 单元素
- 有重复元素时返回下标还是值
- TS 里字符串不可变，改字符要先拆成数组
- Map 的键是值语义（对象当键要注意引用）

## 识别信号

- 题目要你判断『是否出现过』『两数之和』『分组』→ 哈希
- 要求 O(n) 但暴力是 O(n²) → 用哈希/前缀和降复杂度
- 需要统计次数/去重/求交集 → Map / Set

## 番外 · 这个类别里会碰到的三个非哈希套路

必做题里 **#136 只出现一次的数字**、**#169 多数元素**、**#448 找到所有数组中消失的数字** 用哈希能 AC，但各有一个更漂亮的套路，带回它们比做题本身更值。

### A · XOR 异或（#136 专用）

**一句话直觉**：XOR 是「配对消除器」。把所有数都 XOR 到一起，成对的互相抵消，剩下的就是落单的。

**三条你必须记住的性质**（其他全是推论）：

| 式子 | 意思 |
|---|---|
| `a ^ a = 0` | 自己和自己 XOR = 0（**抵消**） |
| `a ^ 0 = a` | 和 0 XOR 不变（**起点**） |
| `a ^ b ^ c = c ^ b ^ a` | 顺序随便换（**交换律 + 结合律**） |

**推理一遍**（这步看懂了就不用背公式）：

假设数组是 `[4, 1, 2, 1, 2]`，4 落单。按顺序 XOR：

```
0 ^ 4 ^ 1 ^ 2 ^ 1 ^ 2
= 4 ^ (1 ^ 1) ^ (2 ^ 2)   // 用交换律把相同的凑到一起
= 4 ^ 0 ^ 0
= 4
```

**模板**：

```ts
let r = 0;
for (const x of nums) r ^= x;
return r;
```

**识别信号**：

- 「所有数都成对，只有一个落单」→ XOR
- 「只出现奇数次 vs 偶数次」→ XOR
- 要求 O(1) 额外空间 + 一次遍历 → XOR 常常是答案

**TS 小坑**：JS/TS 的位运算在 32 位整数上做，LeetCode 的 `number[]` 一般没问题；但如果题目有超过 32 位的大数，XOR 就不能直接用。

### B · Boyer-Moore 投票法（#169 专用）

**一句话直觉**：假设所有数在打群架，**同数抱团，不同数一换一同归于尽**。多数元素占超过一半，不管别人怎么和它对拼，最后站着的一定是它。

**具体做法**：维护两个变量，一个「候选人 `cand`」，一个「它当前的票数 `cnt`」。

```
遍历每个数 x：
  cnt == 0  → 没人在台上，x 自己上，cnt = 1
  x == cand → 自己人，cnt++
  x != cand → 来踢馆的，cnt--（互相抵消一张票）
```

**为什么对**（关键的一句）：

> 多数元素出现次数 > n/2，其他所有数加起来 ≤ n/2。即使其他数全部用来和多数元素对消，多数元素也至少剩 1 张票。所以**最后 `cand` 一定是答案**。

**走一遍** `[2,2,1,1,2,2,1]`（n=7，2 出现 4 次）：

```
x=2  cnt=0 → cand=2, cnt=1
x=2  == cand → cnt=2
x=1  != cand → cnt=1
x=1  != cand → cnt=0
x=2  cnt=0 → cand=2, cnt=1
x=2  == cand → cnt=2
x=1  != cand → cnt=1
最后 cand=2 ✓
```

注意第 4 步 `cnt` 掉到 0，但第 5 步 2 又重新站起来——这就是「多数元素抵消完所有对手还有富余」的直观体现。

**模板**：

```ts
let cand = 0, cnt = 0;
for (const x of nums) {
  if (cnt === 0) cand = x;
  cnt += (x === cand) ? 1 : -1;
}
return cand;
```

**识别信号**：

- 「出现次数严格大于 n/2 的元素」→ Boyer-Moore
- 要求 O(1) 额外空间（排序和哈希都做不到）→ Boyer-Moore
- 变体：「出现次数 > n/3」→ Boyer-Moore 扩展版（维护两个候选人）

**易错**：

- 题目**保证**存在多数元素时才能一遍过；不保证的话要**跑第二遍**数一下 `cand` 的真实次数是否 > n/2
- `cnt` 不是「`cand` 的真实计数」，而是「`cand` 的净剩票数」。两者不一样，别混

### C · 原地标记（in-place marking，#448 同族）

**一句话直觉**：当题目把「值的取值范围」限死在 `1..n`，数组的**下标**就天然是一张 `0..n-1` 的座位表。与其另外开一个 `Set` 记录「谁来过」，不如把「来过」这件事**写在对应的座位上**——用正负号当那一位标记。

**为什么能这么干（三个前提，缺一不可）**：

| 前提 | 作用 |
|---|---|
| 值域被题目限定（`1..n` 或 `0..n-1`） | 值可以当**索引**用 |
| 数组允许被原地修改 | 有地方写标记 |
| 要存的信息只有 **1 bit**（见过 / 没见过） | 只需要符号位，原值用 `abs` 还能还原 |

三个前提凑齐 → 额外空间 **O(1)**，时间仍 **O(n)**。缺任何一个就老实开 `Set`。

**最小走一遍**（只演示「标记」这个动作，不管题目输出）：

假设 `nums = [3, 1, 3]`，值域 `1..3`。约定：**值 x 出现 → 把 `nums[x-1]` 翻转成负数**。

```
x=3  idx=2  nums[2]=3  > 0  → 标记：nums[2] = -3
x=1  idx=0  nums[0]=3  > 0  → 标记：nums[0] = -3
x=3  idx=2  nums[2]=-3 < 0  → 这个座位已经坐过了 → 3 出现了两次
```

遍历结束后：`nums = [-3, 1, -3]`。**座位 i 是正数 ⇔ 值 i+1 从没出现过**——这就是「谁还站着」。

**套到一个完整例子**（#442 数组中重复的数据，值域 `1..n`，找出所有出现两次的）：

```ts
const ans: number[] = [];
for (const x of nums) {
  const idx = Math.abs(x) - 1;   // ← 必须 abs：座位可能已被前面的 x 标记过
  if (nums[idx] < 0) ans.push(idx + 1);  // 第二次来 → 它就是答案
  else nums[idx] = -nums[idx];           // 第一次来 → 坐下
}
return ans;
```

**注意两个循环的分工**：#442 在遍历途中就能顺手收答案；而**有的题答案只能等遍历全部结束后、由第二个循环「读残留的标记」得到**（例：「值域里的哪些数从头到尾没出现过」）。遇到这种题，别急着在第一个循环里找答案。

**易错**：

- `Math.abs(x)` 必须加。漏了就会把「已经被标记成负数的座位」当成 `idx` 为负 → 越界（见下 TS 小坑）
- **值域含 `0` 时这套方法直接失效**：`idx = 0 - 1 = -1`，且 `-0 < 0` 为 `false`，标记立不住。所以它只适用于 `1..n`
- `nums[idx] = -nums[idx]` 而不是 `= -x`：写的是**座位**，值本身不动
- 这题改变了调用方传进来的数组（LeetCode 允许；但如果题目写了「不许修改输入」就不能用）

**TS 小坑**：

```ts
const nums: number[] = [1, 2, 3];
nums[-1];          // 类型是 number，实际是 undefined —— tsc 不报错！
nums[-1] = -5;     // 也不报错，只是给数组加了个 "-1" 属性
```

`strict: true` **不包含** `noUncheckedIndexedAccess`，所以越界读写在编译期完全静默。用 `idx` 前自己保证 `idx >= 0`（即值域从 1 起）。

**识别信号**：

- 「数组长度 n，元素取值在 `1..n`」→ 强烈暗示可以拿值当索引
- 题目点名 **O(1) 额外空间**（或「不许用额外空间」）+ 数组可改 → 原地标记
- 「找出没出现的 / 重复的 / 缺失的数字」→ 同族（#448 / #442 / #645 / #41）
- 反例：「元素值可以任意大 / 有负数」→ 值域前提不成立，退回 `Set`

**自测反问**（合上答案自己答，答不上就重看「三个前提」）：

1. 为什么「正负号」够用，不需要另存一个布尔数组？——因为原值用 `abs` 能还原，1 个 bit 就够。
2. `#448` 的答案是「消失的数字」，它能在第一个循环里就收集吗？还是必须等第二个循环？
3. 如果题目值域是 `0..n-1`，`idx` 该怎么算？和 `1..n` 差在哪一步？
4. 同一个座位被标记两次会怎样？为什么代码里的 `if (nums[idx] < 0)` 正好把这个情况变成了信息，而不是 bug？
