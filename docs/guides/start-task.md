# 起 task 指南（每天开始学习时照这份走）

> 适用：用户说「今天做什么 / 起 task / 开始今天的练习」。
> AI 侧同源 SOP：`.agents/skills/daily-study/SKILL.md`。
> 产物：`ts/docs/daily/<今天>.md`。

## 先问，别自作主张

- **起今日任务文档前先问用户**：`npm run day` 会创建 `ts/docs/daily/<日期>.md`，**同意再写**。
- **默认先问今天想怎么练**：继续当前类型 / 换类型 / 以复习为主 / 今天累少做。用户拍板再动手。
- **不擅自加题、不催进度**；减量、跳过、换类型都由用户决定。
- **不硬造文档**：顺利就不硬补；卡住才记。**文档多 ≠ 做得好。**
- **要改计划（放慢 / 进阶）前先问用户**，同意后才写进 `ROADMAP.md` / `STATE.md`。

## 起 task 流程

1. **摸底（只读）**：读 `ROADMAP.md` / `STATE.md`，最近 2–3 份 `ts/docs/daily/*.md`，`git log --oneline -20`。
   判断今天「继续当前类型 / 回补 / 复习为主 / 进阶」。
2. **先问是否起文档**：说明今天建议（类型 + 选题 + 题量），并**明确问用户**：

   > 「要我现在起**今日任务文档**吗？默认 N 道（题号 + 题名）。也可以调整题量 / 换类型 / 先热身。」

   **同意前不要创建 / 修改任何文件。**

3. **生成骨架**（同意后）：

   ```bash
   cd ts
   npm run day                     # 默认 2 道新题 + 到期复习
   npm run day -- --units 1        # 今天累
   npm run day -- --pattern linked-list
   ```

   → 写 `ts/docs/daily/<今天>.md`（已存在则不覆盖）。

4. **补全 AI 部分**（用 edit 局部填，别重写整份）：
   - **今日主题**：一句话。
   - **今日学习内容（讲解）**：先 `npm run learn -- <pattern>`，写 **5–10 分钟能读完** 的：是什么 / 核心思想 / TS 模板骨架 / 易错边界。**只讲套路，不给完整题解**。
   - 每道题的 **识别信号**。
5. **中文清单**给用户，必须含：**题号 + 中文名 + 英文名 + 难度 + 链接 + 建目录命令**；外加今日复习题、未完成的手写 drill。
6. **红线**：读完讲解立刻动代码；**超过 20 分钟没写代码就跳过**。
7. 开做。收尾按 [commit-guide.md](commit-guide.md)。

## 中途（用户反馈 / 卡住 / AC）

- **卡住**：只答「为什么 / 概念 / TS 语法」，不给完整实现；把卡点写进今日文档「练习过程 · 反馈与讨论」。
- **AC**：补对应题「结果」+ 反馈；同步 `ts/problems/<编号>-<slug>/notes.md` 留白。
- **吃力**：**主动问**是否放慢加深（例：原计划 3 次过 → 延长到 5 次、减新题、加复习），确认后记进文档。
- **记录**：`npm run solve -- <题号> [--first] --min N`（**自动 commit**，计入复习）。

## 文档同步（按需，不硬凑）

| 文档 | 什么时候改 |
|---|---|
| `ts/docs/daily/<日期>.md` | **同意后**由 `npm run day` 生成骨架；中途补反馈；收尾回填复盘 |
| `ts/problems/<编号>-<slug>/notes.md` | 做完 / 卡住时填留白 |
| `STATE.md` | 每次会话结束：阶段 / 当前类型 / 累计 / 下一步 |
| `ROADMAP.md` | **路线真的变了**才改（放慢 / 进阶 / 调整分库） |
| `ts/data/progress.json` | `npm run done -- <drill-id\|pattern-id>` 勾掉热身 |

## 硬规则

- 题目标题以 `ts/data/problems.json` 为准；**永远不要只给题号**。
- **不假设用户「Java 时期全会」**：底层结构当新内容恢复。
- 讲解是薄的；DP 必须拆分推进，绝不连续硬啃。
- 家庭时间不可侵犯（早遛狗 + 健身、晚陪娃）。
